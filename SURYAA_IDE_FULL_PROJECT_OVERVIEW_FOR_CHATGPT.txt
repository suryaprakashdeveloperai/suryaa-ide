1. EXECUTIVE SUMMARY & PLATFORM VISION
================================================================================
Suryaa IDE is a next-generation, professional visual studio designed for building
production-grade Flutter applications backed by high-performance Python (FastAPI),
PostgreSQL 16, and Docker infrastructure.

Unlike traditional drag-and-drop website builders that output fragile or messy code,
Suryaa IDE deterministicly compiles visual canvas component trees directly into:
  1. Clean, Null-Safe, Enterprise Dart code following strict MVVM (Model-View-ViewModel)
     architecture with Provider/ChangeNotifier and GoRouter.
  2. Production-ready FastAPI Python backends with Pydantic v2 validation schemas,
     SQLAlchemy ORM models, Alembic migrations, and JWT authentication.
  3. Resilient Docker Compose environments featuring PostgreSQL 16 with persistent
     Docker storage volumes (ensuring data survives workspace changes).
  4. Real-time streaming pipelines connecting continuous IoT, telemetry, or WebSocket
     feeds directly to dynamic Multi-Axis fl_chart line/bar/pie visualizations.

2. TECHNICAL ARCHITECTURE & STACK
================================================================================

A. FRONTEND (ide_frontend):
  • Core Framework: React 19 + TypeScript 5.7
  • Bundler & Dev Server: Vite 6.4.5 (Lightning fast HMR, dev on http://localhost:3000)
  • State Management: Zustand 5.0 store (`store.ts`) with deep undo/redo history stacks,
    real-time AST state synchronization, and reactive dirty indicators.
  • Styling: TailwindCSS 3.4 + Custom CSS Design System tokens & CSS variables.
  • Code Editor: Monaco Editor (VS Code core engine) with syntax highlighting for
    Dart, Python, YAML, JSON, Dockerfile, and Markdown.
  • Icons: Lucide React (over 40 bespoke vector icons).
  • Build Artifacts: Minified production bundle (dist/assets/index.js + index.css).

B. BACKEND (ide_backend):
  • Web Framework: FastAPI 0.115+ (Asynchronous ASGI server on http://127.0.0.1:8001)
  • Language: Python 3.12 (Strict typing, async/await throughout)
  • ORM & Database: SQLAlchemy 2.0 + SQLite (development) & PostgreSQL 16 (production)
  • Schemas & Serialization: Pydantic v2
  • Security & Hashing: Passlib (Bcrypt) + PyJWT (HS256 Bearer Token authorization)
  • Testing Suite: Pytest 9.1 with pytest-asyncio (11/11 tests passing)
  • Dart Formatter Integration: Google Dart SDK 3.13.7 CLI wrapper for formatting.

C. CONTAINERIZATION & DATABASE PERSISTENCE:
  • Standalone Dockerfile for FastAPI Stream Worker
  • Docker Compose v3.9 orchestration
  • PostgreSQL 16 official image (`postgres:16-alpine`)
  • Named Persistent Volume (`postgres_data:`) mapped to `/var/lib/postgresql/data`
  • Container Isolation: Backend containers run independently from the UI studio.

3.2. ORIENTATION POLICY ENGINE & ADAPTIVE LANDSCAPE SPLITTING
--------------------------------------------------------------------------------
• 3 Orientation Policies:
  1. `🔄 Both (Adaptive Split)` (Default): The application is fully responsive. When rotated
     to landscape (e.g. 852 × 393 px), single vertical columns automatically split into
     a responsive 2-column grid (`grid grid-cols-2 gap-3`), allowing charts, cards, and
     gauges to sit side-by-side gracefully without clipping or vertical squishing.
  2. `📱 Portrait Only`: Locks orientation to vertical portrait. If user clicks rotation,
     a confirmation dialog prompts whether to unlock adaptive mode.
  3. `🖥️ Landscape Only`: Locks orientation to horizontal wide landscape.
• Live Emulator Orientation Toggle:
  - Instant rotate button (`RotateCw`) next to the device badge.
  - Preserves scroll positions, form inputs, and state during rotation.

3.6. FULL-STACK CARD BUILDER (UI-TO-API-TO-DB AUTOMATION)
--------------------------------------------------------------------------------
When dropping or creating a Card or Container:
• The IDE opens the Full-Stack Card Architect modal.
• User enters the Card Title (e.g. "Turbine Pressure Sensor").
• User chooses whether to create an automated API endpoint and Database model.
• The system automatically:
  1. Generates a FastAPI endpoint (`GET /api/v1/turbines/pressure`).
  2. Generates a Pydantic response schema with realistic mock values.
  3. Creates an SQLAlchemy database table model.
  4. Registers the API connector in `apiConnectors`.
  5. Binds the visual widget directly to the API field (`dataBinding: { connectorId, field }`).
  6. Renders live fetched data inside the canvas emulator!
